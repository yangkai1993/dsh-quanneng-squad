# 交付流水线 · 席位即工位（v1.0，2026-11-11）

> 为什么存在：此前 16 席只有「名册 + 回报通道」，没有任何一步规定「这一步缺这个席位就过不去」，
> 于是实测 10 个席位实质产出为 0（含用户点名的提示词优化 / 任务拆分 / 信息收集）。
> 本文件把每个席位绑定为**必经工序**：阶段缺少其「必产物」即不得进入下一阶段。
> 可核查：node packages/dsh-quanneng-squad/scripts/seat-utilization.mjs 逐席比对必产物与实际文件数。

## 硬规则

1. **必经**：任阶段必产物缺失 → 本迭代判未完成，S6 直接阻塞；不得以「已注册/已激活」替代产出。
2. **一人一产物**：每席至少是一个必产物的第一责任人；无必产物的席位属冗余，必须删除或补工序。
3. **提示词是工件**：S1 的岗位提示词须版本化留存（集贤学士负责优化，附上一版 diff 与优化理由），不是临时口头指令。
4. **拆分以「可派工」为验收**：任务树里每卡必须自带写域、并发位次、失败路径，否则退回 S1。
5. **S9 反哺 S1**：太傅改进项若涉及提示词或拆分方式，必须回写 prompts/ 与 decomposition，形成闭环。
6. **并发预算**：同屏 ≤8 席、每轮即时派活 ≤3 卡（宪法 C2 + 宿主 active child limit 8）。
7. **结果核对必经（P-004）**：收口前必须实跑 `packages/dsh-quanneng-squad/scripts/result-verify.mjs`（规范→v0→v1→契约→实现 端到端逐项命中，含「声明≠消费」检查）；它已挂在 release 链上，exit≠0 即本迭代不得收口。**门禁绿 ≠ 任务结果对得上**。

## 回环规则（1.17.0 · S5→S4 fix loop，依据 oh-my-claudecode verify→fix 回环）

1. **触发**：S5 质量验证或 result-verify 出现真实红（非探针红/豁免红）→ 本迭代进入 fix 回环，不得跳过。
2. **动作**：定向返工——只修红项关联的写域文件（dispatch-guard 的 protected_paths 与写域互斥继续生效）；每轮 fix 限时一个迭代，超时升级为 hand_back 由指挥重拆。
3. **复跑**：fix 后必须复跑触发红的那扇门 + 全链 release；绿了才可回 S5 收口。
4. **留痕**：每轮 fix 在 docs/squad/retro-<迭代>.md 记一条（红门→修复→复跑证据），S9 太傅汇总。
