## 三、优化后的可复用提示词模板（用户以后可直接套用）

```text
【任务】<一句话目标>
【输入】<文档/代码/现状指针，必须 file:line>
【交付序列】先给可调整方案 → 我确认后再精修 → 再实现（不要跳步）
【过程可见】每轮开工给我看：拆解（哪些卡/派给谁/令牌）、收尾给我看：汇总（交付/验收/问题/门禁/风险/下一步）；用实时界面，不要事后长文
【验收】端到端核对「最初输入 → 最终产物」逐项覆盖；不只是跑测试/门禁
【小队】16 席按 S-1~S9 工位全部有必产物；用户提示词、情报对标、记注对账是每次派活前提
【记忆】本地为主、云端辅助；云端不可达不得影响结论
【失败处理】发现 bug 立即修并自纠正；模型/路由变化不得让小队停摆
```

## 四、给 captain 的硬规则（从 U7/U8/U9 推导）

1. 用户提需求 → 先读本文件，把原话映射到 U1~U9，缺哪条补哪条；
2. **每轮必须用 `ui_present` 或等价实时界面展示拆解与汇总**，不能只在对话末尾贴文字；
3. 收口前必须跑「端到端覆盖核对」脚本，输出规范 API / 决策项 / 冲突项 / 冻结约束 的逐项命中表，而不是只贴 `verify 43/43`；
4. 提示词优化工位（集贤学士）必须同时维护 `user-prompts/`（用户侧）与 `prompts/`（角色侧）两套索引。
