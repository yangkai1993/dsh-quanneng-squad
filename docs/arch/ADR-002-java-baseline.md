# ADR-002 · 回到 Java 基线（取代 ADR-001）

| 项 | 值 |
| --- | --- |
| 状态 | **已决策（用户 A4 拍板）** |
| 日期 | 2026-11-06 |
| 取代 | ADR-001（其「采纳 A 纯 Node ESM」结论被推翻） |
| 影响面 | 全部 `src/`、`package.json`、`tests/`、契约/宪法/AGENTS/部署 |

## 决策
采用预设 `squad-arch` 基线：**Java 17（JDK21 编译 release 17）+ Spring Boot 3.5.16 + MySQL 8 + Redis**；国密经 **BouncyCastle bcprov/bcpkix** 实现（Java 标准库无 SM2/SM3/SM4）。前端 Vue3 栈因本任务无 UI 需求列为后续可选，本轮不建。

## 背景
ADR-001 曾以「零依赖、已跑通、迁移成本最高」为由推荐纯 Node ESM；太傅票拟「慎行」并指出预设基线被静默覆盖属程序问题。用户明确选择「回到 Java 基线」→ 技术结论让位于用户明示决策。

## 备选（四维：可行性/成本/合规/演进，0–5）
| 备选 | 可行性 | 成本 | 合规(对齐预设) | 演进 | 合计 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **C Java17+SpringBoot3.5.16+MySQL8+Redis** | 4 | 2 | **5** | 4 | **15** | **采纳（用户明示）** |
| A 纯 Node ESM 零依赖（现状） | 5 | 5 | 1 | 5 | 16 | 否：与预设冲突，用户已推翻 |
| B Node + npm 国密库 | 4 | 4 | 1 | 4 | 13 | 否 |
| D Java + 自研纯 Java 国密（不引 BC） | 3 | 2 | 4 | 3 | 12 | 备选：若 Central 不可达则降级 |

> 注意：A 分数更高但被用户明示否决——**合规（对齐预设基线）为硬约束**，不适用纯分数排序。

## 被否方案理由
- A/B：用户 A4 已否决。
- D：BouncyCastle 是国密生产标准库；自研仅作离线兜底。

## 后果
- 已有 20 个 Node 模块与 11/11 测试归档为 `legacy-node/` 或保留 `src/` 并标注历史；本轮新建 Java 工程于 `gateway-java/`。
- 契约常量、签名串顺序、encryptData 四子域、应答码三层、状态机语义**保持不变**（业务契约不因技术栈变更而改）。
- 推翻条件：用户再次改判 / 入网方明确要求非 Java 栈。
