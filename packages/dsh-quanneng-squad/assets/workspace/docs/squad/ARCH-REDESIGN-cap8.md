# 全能小队重设计 · 在宿主 8 席约束下囊括全部设计理念

> 本文基于 **2026-11-06 四轮实测**，不是推演。修正了此前「累计上限」的错误表述。

## 一、真实约束模型（逐条实测）

| # | 约束 | 实测证据 | 影响 |
| --- | --- | --- | --- |
| C1 | **并发 8 席**，`agent_teams_add_member` 与 `spawn_teammate` 共享同一池 | 第 9 人 add / spawn 均报 `member cap (8)` / `Team member limit 8 reached` | 同屏最多 8 teammate |
| C2 | `remove_member` **释放席位**，可立即 add 新名字 | remove 前端经理 → 8→7 → add 测试经理 → 7→8 成功 | 换班可行 |
| C3 | **名字永久占额**：同名角色不能二次 add | 撤回 5 人后再 add 原名 → `has already been used in team` ×5 | 需别名或换 team |
| C4 | 别名可绕开 C3 | add `产品经理-轮2` → ok/idle | 每轮新别名即可复用角色 |
| C5 | **单会话单 team** | `agent_teams_create` 第二次 → `you already lead team "quanneng-squad"` | 不能靠多 team 扩容 |
| C6 | `squads_run_member` **不受 cap 限制** | 全编 16 人逐员 ok/running（两轮 + 本轮共三轮 16/16） | 派活通道无限 |
| C7 | `squads_run_squad` / `list_agents` 16 可见 / `send_message` 按中文名 | 恒 FAIL（宿主缺 `list-agents` 子插件，见 INTERACTION §八） | 不要押在这些工具上 |
| C8 | 成员会话**不自动写正文** | 10 次派活后 rerun/ 0 落盘，需指挥代落并标注 | 回报通道要显式设计 |
| C9 | 成员回报经 `agent_teams_send_message(to=captain)` → `delivered:live` + inbox 文件 | 6 名 spawn 成员、8 名 team.json 成员实测 | 文件总线是唯一可靠回收 |

**结论：上限是「同时在场的 teammate 席位」，不是「团队总人数」。** 16 人编制完全可保留，只需把「同时在场」重定义为**按阶段换班**。

## 三、核心机制：席位预算 + 轮次名册 + 别名去重

### 3.1 轮次名册（每轮 ≤8 席，覆盖 16 角色需 ≥2 轮）
| 轮次 | 阶段 | 在席角色 | 席数 |
| --- | --- | --- | --- |
| W1 | S-1 谋断门 | 翰林、采风、集贤、太傅、需求、产品、给事中、御史 | 8 |
| W2 | S0 + 架构 | 需求、产品、架构、给事中、御史、后端、测试、交付 | 8 |
| W3 | 实现 + 初审 | 前端、后端、架构、测试、御史、运维、交付、需求 | 8 |
| W4 | S8 复盘 + 门禁 | 考功、起居注、给事中、御史、交付、需求、产品、架构 | 8 |

16 个角色在 4 轮中**全部上场**，且每轮不超 8 席。跨轮重复角色用 C4 别名：`需求经理@W2`、`需求经理@W3`……（或换 team，但 C5 限制单会话，故别名更稳）。

### 3.2 席位生命周期（可执行 SOP）
```
轮次开始：
  for r in 本轮名册: agent_teams_add_member({name: r.alias, preset: r.preset})   // ≤8
  for r in 本轮名册: agent_teams_send_message({to:r.alias, content: 任务书+唯一落盘点})  // delivered:wake
  （如需全编派活）squads_run_member 16/16 并行，不受席位限制
轮次结束：
  回收：读 docs/squad/inbox/<角色>.md + rerun/<阶段>.md；成员回执 delivered:live
  for r in 本轮名册: agent_teams_remove_member({name:r.alias, confirm:true})  // 释放席位
  记注：journal 追加「W<n> 换班：释放 8 席 / 回收 N 份回报」
下一轮：用新别名重新 add（避开 C3 名字占额）
```

### 3.3 为什么这能囊括「全部」理念
1. **不删角色**：16 人编制、preset、权限、brief、角色稿、dispatch/inbox 全部保留。
2. **不降并发纪律**：每轮 ≤8 且并发任务 ≤3（宪法 C2），目录互斥（AGENTS §1）。
3. **不丢流水线**：S-1→S0→实现→科抄/抽巡→门禁→S8 全部有专属轮次，不再互相挤占。
4. **不假装 16 同屏**：向用户明示「编制 16 / 同屏 8 / 换班 4 轮全覆盖」，这是设计选择而非缺陷。
5. **不依赖坏工具**：不用 `squads_run_squad` / `list_agents` / `send_message` 按中文名（C7）；改用 squads_run_member + agent_teams_send_message + 文件总线（C6/C9）。

## 五、若宿主未来放开 cap
换班机制不必废弃：它是**节流与并发纪律**的载体（宪法 C2），放开后只是把 W1~W4 合并为单轮 16 席，轮次名册仍可作阶段门控。设计向前兼容。
