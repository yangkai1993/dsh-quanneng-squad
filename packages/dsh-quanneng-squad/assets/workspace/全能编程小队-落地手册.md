## §0 宪法层（永不自动变更，用户专属）

1. 三权分离：中书（起草）/ 门下（给事中封驳）/ 御史台（御史大夫独立监察、安全一票否决）。
2. 目录所有权：并行任务目录互斥，见 `AGENTS.md §1`。
3. 制衡结构：给事中与御史互不隶属、互相监督；太傅票拟与集贤推荐相互独立。
4. 文档总线三律：消息只做指针不做载体 / 派活必引用落盘文档 / 文档上没有 = 没发生。
5. 指挥不写业务代码：实现一律派给成员会话；指挥只读代码、读文档、写计划、做验收。
6. 并行纪律：每轮并发 ≤ 3；并行任务目录互斥；修复循环 S5 最多 3 轮。
7. Git 纪律：默认不 commit/push；交付阶段经用户确认后由交付发布经理统一执行。

## §1B 三省六部流水线

```
用户粗稿
  → S-1 谋断门（翰林会诊 → 采风情报 → 集贤风暴 → 太傅票拟 → 用户拍板）
  → 需求经理落基线 → S0 拷问门（价值/边界/隐含假设/验收，≤2 轮）
  → 中书起草（各经理按令权表：一令一主 / 无抄不施 / 令必落卡）
  → 给事中科抄（PRD/契约/宪法/门材料必经；抄可 | 封驳 | 留）
  → 总指挥终审
  → 实现域经理派员工（subagent，提示词首行 squadRole: 注入 roles/ 角色稿）
  → 经理初审（验收对表/越权 diff/EARS 真实现/无谎报/宪法合规）
  → 门禁 G-S1…G-S7 落 docs/squad/gates/
  → 御史大夫抽巡（每 gate 后抽 1 个已通过故事独立复核）
  → 起居注官记注 + 一致性核查
  → 考功郎中 S8 度量与五态管线
  → 交付发布经理发布清单（用户确认后 commit/tag）
```

令权表见 `squad-toolkit/templates/AUTHORITY.md`。成员间禁止直接对话，信息经总指挥中转或共享文件。

## §3.6 技能与工具选择纪律

第一动作 = 对表系统注入的 `<available_skills>` 与宿主工具目录；匹配即用 skill 工具按准确名加载；本队场景优先用 `squad-toolkit` 模板；无匹配才 DIY 并在回报注明。派活时把「先查技能目录」写进任务书第一动作。

## §3A 文档总线协议

每次派活/验收/裁决必须引用一个落盘文档路径；纯口头消息无效。派卡必含「同步更新相关文档」任务项（漏更 = 卡未完成，初审退回）。CR approved 后令交付经理发起变更召回，逾期由起居注台账冻结相关故事卡。
